# 🧬 [1.4] Наследование, `extends`, родительские и дочерние классы.
### Мы уже знаем, что класс может описывать объект:
    class Student {
        String name;
        int age;
    }
### Теперь представим, что в нашей системе есть: `Student`, `Teacher`, `Admin`.
### У них могут быть общие свойства: `id`, `name`, `age`.
### И общие методы: `getName()`, `getId()`.
### Можно сделать три польностью независимых класса:
    class Student {
        String name;
        int age;
        ...
    }

    class Teacher {
        String name;
        int age;
        ...
    }
    
    class Admin {
        String name;
        int age;
        ...
    }
### Но появляется дублирование:
    Student ── name
            └─ age
    
    Teacher ── name
            └─ age
    
    Admin ─── name
            └─ age
### Если общая логика изменится, её придется менять в нескольких местах.
### Наследование помогает вынести общую часть в родительский класс.
# 👪 [1.4.1] Родительский и дочерний класс
### Например:
    class Person {
        String name;
        int age;

        void introduce() {
            System.out.println("Меня зовут " + name);
        }
    }
### Теперь:
    class Student extends Person {

    }
### `Person` - родительский класс.
### `Student` - дочерний класс.
# 🎒 [1.4.2] `extends`
### Ключевое слово `extends` означает: `Дочерний класс наследует доступные ему члены родительского класса.`
### Например:
    class Person {
        String name;
    
        void sayHello() {
            System.out.println("Hello");
        }
    }

    class Student extends Person {
    }
### Теперь можно:
    Student student = new Student();

    student.name = "Andrey";
    student.sayHello();
### Хотя `name` и `sayHello()` были объявлены в Person.
# 🔎 [1.4.3] Аналогия
### Представим: Person = базовая модель человека.
### А: Student = человек + особенности студента.
### То есть:
    Person
    ├── name
    ├── age
    └── sayHello()
    
    Student
    ├── всё доступное от Person
    └── свои особенности
### Поэтому наследование можно представить как: `Я беру существующий класс и создаю более специализированный вариант.`
# ❗ [1.4.4] Наследование не копирует исходный код
### Когда пишем: `class Student extends Person`
### Это не означает, что Java буквально копирует весь исходный текст Person внутрь Student.
### Создается наследование отношения между классами.
### Условно: `Student IS-A Person`
### Это называется отношением `is-a`, т.е. Студент - это человек.
### Примеры:
### Dog IS-A Animal.
### Cat IS-A Animal.
### Student IS-A Person.
### Manager IS-A Person.
### То есть: Дочерний объект является родительским типом.
### Поэтому: `Person person = new Student();` допустимо.
### Student является Person.
# 📦 [1.4.5] HAS-A
### В Java HAS-A означает, что один класс содержит объект другого класса в качестве своего поля.
### Например:
    class Car {
        private Engine engine;

        public Car() {
            this.engine = new Engine();
        }

        public void drive() {
            engine.start();
            System.out.println("Машина едет");
        }
    }
### Car имеет поле Engine.
### Машина имеет двигатель.
# ❓ [1.4.6] Что получает дочерний класс
### Например:
    class Person {

        String name;
    
        void sayHello() {
            System.out.println("Hello");
        }
    }

    class Student extends Person {
    
        int grade;
    }
### У Student появится собственное поле: `grade` и унаследованная часть: `name`, `sayHello()`.
### Но здесь очень важно помнить про модификаторы доступа.
# 🔒 [1.4.7] `private` не становится доступным напрямую
### Например:
    class Person {

        private String name;
    
        public String getName() {
            return name;
        }
    }
### Теперь: `class Student extends Person { }`
### Student не может напрямую написать: `name = "Andrey";`
### Потому что: `name - private`
### Но может использовать доступный метод: `getName();`
### То есть, наследование не отменяет правила инкапсуляции.
# 🛡️ [1.4.8] `protected`
### Есть специальный модификатор: `protected`
### Например:
    class Person {

        protected String name;

    }
### Он предоставляет доступ внутри самого класса, его наследникам и некоторым классам того же package.
### Например:
    class Student extends Person {

        void printName() {
            System.out.println(name);
        }
    }
### Сработает. Но `protected` нужно использовать осознанно. В реальном проекте предпочтительнее использовать `private`.
# 🗺️ [1.4.9] Конструкторы и наследование
### Представим:
    class Person {

        String name;
    
        Person(String name) {
            this.name = name;
        }
    }
### И:
    class Student extends Person {

    }
### Теперь попробуем: `Student student = new Student();`
### Может возникнуть ошибка, потому что при создании Student нужно инициализировать родительскую часть Person.
### А у Person нет конструктора без параметров.
### Когда создаем: `Student student = new Student();`
### Должна быть создана не только часть Student, но и родительская часть Person.
### Упрощенная схема:
    new Student()
            ↓
    создаём Person-часть
            ↓
    создаём Student-часть
### Поэтому дочерний конструктор должен обеспечить вызов подходящего конструктора родителя.
### Для этого существует: `super()`
# 👑 [1.4.10] `super()`
### Например:
    class Person {

        String name;
    
        Person(String name) {
            this.name = name;
        }

    }
    
    class Student extends Person {
    
        Student(String name) {
            super(name);
        }
    }
### Теперь: `Student student = new Student("Andrey");`
### Происходит примерно так:
    Student(...)
        ↓
    super("Andrey")
        ↓
    Person(...)
        ↓
    this.name = "Andrey"
# ❓ [1.4.11] Что если `super()` не написать
### Если в дочернем конструкторе мы не написали `super(...);`, Java попытается использовать: `super();` автоматически.
### Концептуально означает попытку:
    Student() {
        super();
    }
### Но это сработает только если у родителя существует доступный конструктор без аргументов.
# 🧗 [1.4.12] Дочерний класс расширяет родителя
### Это одна из главных идей:
    Person
        ↓
    общая функциональность
        ↓
    Student
        ↓
    специализированная функциональность
