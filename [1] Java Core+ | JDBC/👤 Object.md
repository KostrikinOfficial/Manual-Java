## 👤 Класс `Object`
### `Object` - это...
Базовый класс для всех классов. Любой класс неявно наследуется от `Object`, даже без ключевого слова `extends`.

Поэтому методы, объявленные в `Object`, доступны обычным объектам через наследование. Среди них особенно важны:

`toString()`

`equals()`

`hashCode()`
## 📚 Связь с коллекциями
Позже мы узнаем о `HashMap`, `HashSet`. И там Java должна понимать: «Эти два объекта считаются одинаковыми или разными?»

Для этого используются методы: `hashCode()`, `equals()`.

## ⚙️ Метод `toString()`
### `toString()` - это...
Метод, который возвращает строковое представление объекта.

Например: `System.out.println(student);`

Мы можем не писать: `student.toString()`, потому что `println()` автоматически обращается к `toString()` для объекта.
### Как использовать `toString()` профессионально?
Хороший `toString()` обычно должен отвечать: «Что сейчас собой представляет этот объект?»

Например:

    @Override
    public String toString() {
        return "Student{" +
        "id=" + id +
        ", name='" + name + '\'' +
        ", age=" + age +
        '}';
    }

Это удобно: `System.out.println(student);`, вместо ручного вывода каждого поля.
## ⚙️ Метод `equals()`
### `equals()` - это...
Метод, который сравнивает объекты, и отвечает на вопрос: «Равны ли они?»

Предположим:

`Student s1 = new Student("Andrey");`

`Student s2 = new Student("Andrey");`

В памяти это два отдельных объекта. Вопрос: «Считаем ли мы их одинаковыми?»

Java не может угадать наши бизнес-правила. Для этого используется: `equals()`.

### Переопределение `equals()`
Представим сущность:

    Student
    id = 100;
    name = "Andrey";
    age = 18;

Если `id` однозначно идентифицирует студента, можно определить: «Два Student равны, если у них одинаковый `id`»
    
Тогда:

    @Override
    public boolean equals(Object obj) {
        ...
    }

### `==` и `equals` — это не одно и тоже!
Для объектов: `s1 == s2` обычно проверяет: «Являются ли две ссылки ссылками на один и тот же объект?»

А: `s1.equals(s2)` проверяет логическое равенство, согласно реализации `equals()`

### `equals()` не отвечает на вопрос «один ли этот объект в памяти?». Он отвечает на вопрос «считаем ли мы эти объектами логически равными?»

## ⚙️ Метод `hashCode()`
### `hashCode()` - это...
Метод, который возвращает целое число, связанное с состоянием объекта.

Например, `s1.hashCode()` может получить: `12345678`, значение нас не интересует. Важное другое:

`hashCode()` помогает быстро организовать поиск объектов в hash-структурах. Например:

`HashMap`,

`HashSet`.
### Зачем вообще нужен `hashCode`?
Представим огромный склад: 1 000 000 объектов. Если для поиска каждого объекта сравнивать его с каждым другим:

    Объект
    ↓
    Сравнить с 1
    ↓
    Сравнить с 2
    ↓
    ...

Это дорого. Хеширование позволяет сначала определить область поиска. Упрощенно:

    object
    ↓
    hashCode()
    ↓
    bucket
    ↓
    проверка нужных объектов

То есть, `hashCode()` помогает сузить поиск.

## 🔃 `hashCode()` и `equals()` связаны.
Главный контракт: Если `s1.equals(s2)` возвращает `true`, то `s1.hashCode()` и `s2.hasCode()` должны быть одинаковыми.

Обратное утверждение необязательно.

Если: `s1.hashCode() == s2.hashCode()`, это ещё не означает: `s1.equals(s2)`.

Потому что разные объекты могут получить одинаковый hash. Это называется коллизия.

## 🎡 Коллизия
Представим:

`s1 → hash 100`,

`s2 → hash 100`.

Это не означает: `s1 == s2` или `s1.equals(s2)` → `true`.

Просто они попали в один hash bucket. Поэтому hashCode используется для быстрого поиска кандидатов, а `equals()` помогает окончательно определить равенство.

## 🚀 Современный Java способ
Для классов-данных часто используют: `record Student(int id, String name) { }`

`record` автоматически предоставляет реализации, связанные с вышеперечисленными методами.
