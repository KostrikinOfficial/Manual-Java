# 🧪 [1.3] JUnit, `@Test`, assertions и структура тестов
### В этом разделе мы должны перейти от идеи:
### `Я написал код и сам посмотрел, работает ли он.`
### К:
### `Я написал правило, по которому программа сама проверяет, правильно ли работает метод.`
# 🧪 [1.3.1] Что такое JUnit
## `JUnit - инструмент автоматического тестирования.`
### JUnit - популярный фреймворк для тестирования Java-кода.
### Он позволяет написать:
    @Test
    void shouldCalculateSum() {
        ...
    }
### И затем Maven/JUnit сможет автоматически запустить этот тест.
### Главная идея: `Java-код ⭢ Тест ⭢ Проверка ⭢ PASS/FAIL`
# ❓ [1.3.2] Зачем нужны автоматические тесты
### Представим наш метод:
    public int add(int a, int b) {
        return a + b;
    }
### Мы можем вручную проверить: `2 + 3 = 5`
### Потом изменить код. Например, случайно:
    public int add(int a, int b) {
        return a - b;
    }
### И уже забыть, что раньше этот метод должен был складывать.
### Ручная проверка становится неудобной.
### JUnit позволяет написать: `2 + 3 должно быть 5`
### И потом выполнять эту проверку автоматически много раз.
# 🔎 [1.3.3] Аналогия
### Представим завод: Есть станок, который производит детали.
### Мы можем каждый раз брать деталь и вручную измерять:
### `Длина = 10 см?`
### `Длина = 5 см?`
### Но намного лучше поставить автоматический контроль:
### `Деталь ⭢ Проверка ⭢ Соответствует(✅)/Не соответствует(❌)`
# ❓ [1.3.4] Что именно проверяет тест
### JUnit сам по себе не знает, каким должен быть результат нашей программы.
### Например: `int result = calculator.add(2, 3);`
### JUnit не знает что result должен быть 5, пока мы ему не скажем.
### Для этого используются `assertions` - утверждения.
# 🔬 [1.3.5] Assertion
### Assertion можно понимать как:
### `Я утверждаю, что результат должен соответствовать определенному условию.`
### Например: `assertEquals(5, result);`
### Мы говорим: `Ожидаем 5, фактический результат должен быть result`
### Если значение соответствует - тест проходит. Если нет - тест падает.
### JUnit предоставляет набор assertion-методов, а при невыполнении assertion тест считается неуспешным.
# 🧫 [1.3.6] Expected и Actual
### В: `assertEquals(5, result);`
### Есть: expected - ожидаемое значение.
### И: actual - фактическое значение.
### То есть expected = 5, actual = 5 ⭢ ✅
### А если expected = 5, actual = 4 ⭢ ❌
# ⚗️ [1.3.7] `@Test`
### Самая базовая аннотация: `@Test`
### Она говорит JUnit: `Этот метод является тестовым методом и его нужно рассмотреть как тест.`
### Например:
    import org.junit.jupiter.api.Test;

    class CalculatorTest {

        @Test
        void additionWorks() {
            // test
        }
    }
### JUnit увидит: `additionWorks()` как тест.
# ❓ [1.3.8] Почему аннотация нужна
### Обычный метод:
    void additionWorks() { }
### Сам по себе не означает для JUnit: `Запусти меня как тест!`
### А:
    @Test
    void additionWorks() { }
### Уже говорит JUnit: `Это тестовый метод.`
# ❗ [1.3.9] Тест - тоже код.
### Тест:
    @Test
    void additionWorks() { }
### — Это не какая-то магическая настройка.
### Это обычный Java-метод, который запускает JUnit по своим правилам.
### Поэтому тест нужно писать: понятно, читаемо, без лишней логики, с хорошими именами.
# 📐 [1.3.10] Arrange → Act → Assert
### Одна из самых полезных моделей при тестировании:
### `Подготовь → Выполни → Проверь`
## Этап Arrange (подготавливаем данные)
    Calculator calculator = new Calculator();
    int a = 2;
    int b = 3;
## Этап Act (выполняем действие)
    int result = calculator.add(a, b);
## Этап Assert (теперь проверяем)
    assertEquals(5, result);
## Полный пример:
    import org.junit.jupiter.api.Test;

    import static org.junit.jupiter.api.Assertions.assertEquals;

    class CalculatorTest {

        @Test
        void additionWorks() {
            // Arrange
            Calculator calculator = new Calculator();

            // Act
            int result = calculator.add(2, 3);

            // Assert
            assertEquals(5, result);
        }
    }
# 🎯 [1.3.11] Основные методы проверки:
| Assert                | Что проверяет                        | Пример                                                                    |
| --------------------- | ------------------------------------ | ------------------------------------------------------------------------- |
| `assertEquals()`      | Значения равны                       | `assertEquals(5, result);`                                                |
| `assertNotEquals()`   | Значения не равны                    | `assertNotEquals(10, result);`                                            |
| `assertTrue()`        | Условие `true`                       | `assertTrue(age >= 18);`                                                  |
| `assertFalse()`       | Условие `false`                      | `assertFalse(age < 18);`                                                  |
| `assertNull()`        | Значение `null`                      | `assertNull(student);`                                                    |
| `assertNotNull()`     | Значение не `null`                   | `assertNotNull(student);`                                                 |
| `assertThrows()`      | Выбрасывается ожидаемое исключение   | `assertThrows(IllegalArgumentException.class, () -> service.create(-1));` |
| `assertSame()`        | Это один и тот же объект             | `assertSame(student1, student2);`                                         |
| `assertNotSame()`     | Это разные объекты                   | `assertNotSame(student1, student2);`                                      |
| `assertArrayEquals()` | Массивы содержат одинаковые элементы | `assertArrayEquals(new int[]{1, 2}, array);`                              |
