# 🎭 Полиморфизм, Overriding, Overloading
### Полиморфизм - это...
Способность программы работать с объектами разных типов через единый общий интерфейс или родительский класс так, будто они одинаковые, но при этом каждый объект выполняет действие по-своему.
### Если проще, полиморфизм - это...
Один метод, но разное поведение в зависимости от объекта.
### Представим, что мы разрабатываем свою систему зелий в нашей игре:
    class Potion

    ПОЛЯ
    int size;
    double price;

    МЕТОДЫ
    void drink(Character character) {

    }
### А дальше, можем создать конкретные классы зелий, например зелье здоровья:
Наследуем его от базового класса и получаем копии всех полей и методов.
    
    class HealthPotion extends Potion

Но есть важная деталь: метод `drink()` который мы унаследовали - пустой. Ведь мы не могли ничего в нем написать для базового класса, так как у базового зелья нет никакого эффекта. А вот у конкретного, эффект быть должен. Так что в классе зелья здоровья мы можем снова написать эту функцию `drink()`, но уже добавить туда код:

    class HealthPotion extends Potion

    МЕТОДЫ
    void drink(Character character) {
        character.hp += 10;
    }

То что мы сделали, называется переопределением метода. Это ситуация, когда один класс наследуется от другого, но его не устраивает то, как работает метод, копию которого он получил от базового. Тогда он он может в этом методе иметь свой собственный - именно подходящий ему код и переопределить его.
### Но зачем этот метод в базовом классе, может его выпилить и тогда в каждом классе будет свой собственный метод, а не наследуемый?
Потому что мы можем сказать: «У каждого зелья должно быть последствие!». А конкретное зелье уже решает, какое именное последствие у персонажа будет.
## 🔄 Динамический полиморфизм (переопределение методов / overriding)
- Родительский класс задает общий метод, а дочерние классы меняют его под себя.
- Программа сама понимает в момент работы (на лету), чей именно метод запустить.
### Теперь:
    Potion potionHealth = new HealthPotion();
    Potion potionMana = new ManaPotion();

    potionHealth.drink();
    potionMana.drink();
### Получаем:
    +10 HP
    +10 MANA
Один и тот же вызов: `drink()` ведёт себя по-разному в зависимости от конкретного объекта.
Именно это и есть одна из главных идей полиморфизма.
### Переопределение (`overriding`) - когда дочерний класс предоставляет собственную реализацию унаследованного метода.
Аннотация `@Override` говорит компилятору: «Я ожидаю, что этот метод переопределяет метод родителя».
### Например:
    @Override
    void drink(Character character) {
        character.hp += 10;
    }
И если мы оши ошибёмся:

    @Override
    void drinks(Character character) {
        character.hp += 10;
    }

Компилятор сообщит, что такой метод родителя не переопределяется.
### Почему `@Override` полезен?
Вернемся к примеру выше, представим что мы случайно совершили такую ошибку:
- Без `@Override` Java может воспринять это как новый метод.
- С `@Override` ошибка обнаружится сразу.
Поэтому профессиональный Java-код обычно использует эту аннотацию при каждом переопределении.
## ⏱️ Статический полиморфизм (перегрузка методов / overloading)
- Внутри одного класса создаются методы с одинаковыми именами, но разным набором параметров.
- Компилятор выбирает нужный метод ещё до запуска программы в зависимости от того, что в него передали.
### Пример статического полиморфизма:
Здесь имя метода `drink()` одинаковое, но компилятор ещё до запуска программы точно знает, какой метод вызвать, глядя на тип/порядок/количество данных.
    
    class Potion

    ПОЛЯ

    МЕТОДЫ
    void healthPotion(Character character, boolean isHealthEffect) {
        hp += 10;
    }

    void manaPotion(Character character, boolean isHealthEffect, boolean isManaEffect) {
        mana += 10;
    }

## 🆚 Overriding vs Overloading
### Overriding - переопределение.
- Программа определяет метод в процессе работы.
- Основной механизм: переопределение методов / интерфейсы.
- Медленнее (тратится время на поиск в таблице vtable).
- Не влияет на размер кода существенно.
- Возможны ошибки приведения типов в процессе работы.
### Overloading - перегрузка.
- Компилятор определяет нужный метод до запуска программы (по аргументам).
- Основной механизм: перегрузка методов / шаблоны.
- Быстрее (нет накладных расходов).
- Может увеличивать размер кода из-за генерации шаблонов.
- Строгая проверка ошибок (ошибки типов видны сразу).
