## 🔗 `LinkedList`
### `LinkedList` - это...
Реализация интерфейсов, среди которых нас сейчас прежде всего интересует `List`

Внутри она основана на связанных узлах.

Условно: `[A] ↔ [B] ↔ [C] ↔ [D]`, где каждый узел связан с соседними.

В Java `LinkedList` реализует двусвязанную структуру: `предыдущий ← узел → следующий`

Поэтому концептуально: `null ← A ↔ B ↔ C ↔ D → null`

### `List<String>`
Использование выглядит знакомо: `List<String> names = new LinkedList<>();`

`List<String>` снова, потому что мы программируем через интерфейс.

### Почему `LinkedList` может быть хорош
Есть: `[A] ↔ [B] ↔ [C] ↔ [D]` и у нас есть уже нужный узел.

Чтобы вставить новый: `[A] ↔ [B] ↔ [X] ↔ [C] ↔ [D]` нужно изменить связи между узлами

Сами элементы при этом не приходится физически сдвигать в одном большом массиве.

Поэтому операции вставки/удаления при наличии позиции/узла могут быть очень эффективны.

Изменение связей вокруг уже найденной позиции может быть О(1), но поиск этой позиции может занять О(n)

### Важный ньюанс
Новички часто запоминают: `LinkedList` - быстро вставляет элементы. Это слишком грубо.

Например: `list.add(500000, "X");` Чтобы добраться до позиции `500000`, всё равно нужно сначала найти нужный узел.

### Добавление в начало и конец
Например:

    LinkedList<String> list = new LinkedList<>();
    
    list.addFirst("Андрей");
    list.addLast("Мария");

Получим: `[Андрей, Мария]`

Операции `addFirst()` и `addLast()` могут выполняться за О(1)

## 📦 Сравнение с `ArrayList`
### `ArrayList`
`[A][B][C][D][E]` - один внутренний массив.
### `LinkedList`
`[A] ↔ [B] ↔ [C] ↔ [D] ↔ [E]` - отдельные узлы, связанные между собой. Это напрямую влияет на производительность операций.
### `get()` - важное различие.
Рассмотрим: `list.get(500000);`

`ArrayList` имеет прямой доступ к массиву:

    индекс
    ↓
    [0][1][2][3]...[500000]
                        ↑

Поэтому доступ к индексу очень быстрый: `O(1)`

`LinkedList` чтобы добраться до элемента м индексом `500000`, нужно пройти по цепочке узлов до нужной позиции.

Это: `O(n)`

Поэтому для частого `get(index)`, `ArrayList` обычно значительно лучше `LinkedList`

### Упрощённое сравнение:
| Операция                    |                   ArrayList |                         LinkedList |
| --------------------------- | --------------------------: | ---------------------------------: |
| `get(index)`                |                        O(1) |                               O(n) |
| добавление в конец          | обычно O(1) амортизированно |                               O(1) |
| добавление в начало         |                        O(n) |                               O(1) |
| удаление из начала          |                        O(n) |                               O(1) |
| вставка/удаление в середине |                        O(n) | O(n) поиск + O(1) изменение связей |

### Почему `ArrayList` часто остается хорошим выбором
Может показаться: `LinkedList` же умеет быстро вставлять - значить всегда надо использовать его.

Нет. `ArrayList` часто удобен благодаря:
- Быстрому `get(index)`
- Компактному хранению
- Хорошей работе с памятью/кэшем процессора

### Когда можно рассматривать `LinkedList`
Условно:
- Частые операции на концах списка
- Структура, где важны операции вставки/удаления

Например:

    LinkedList<String> queue = new LinkedList<>();
    
    queue.addLast("A");
    queue.addLast("B");
    queue.removeFirst();

Но в реальном Java-коде для очередей часто используют специализированный интерфейс и реализации, например `Deque`
